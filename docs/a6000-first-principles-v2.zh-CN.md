## 1. 硬件环境与实测物理上限

本报告全部数据均在独占 GPU 窗口内实测取得，所有有效对比臂均满足 **0 热节流**（NVML 热降频计数 `0`、解码峰值温度 `<= 74 °C`、冷预填 `<= 83 °C`）与 **0 CPU 干扰**：

| 硬件维度 | 实测条件与物理上限 | 证据等级 |
| --- | --- | --- |
| GPU | NVIDIA RTX A6000 48 GB（Ampere `sm_86`，WDDM 驱动 597.30，300 W TDP） | 实测 |
| 显存带宽与时钟 | 持续读 **`713.0 GB/s`**（标称 `768.1 GB/s`）；CUDA P2 计算态锁频 **`7601 MHz`**（空闲尾部回落 `405 MHz`） | 实测 |
| FP32 算力 | **`38.7 TFLOPS`** | 实测 |
| 宿主与总线 | 双路 AMD EPYC 7542（64C/128T，双 NUMA，256 GiB DDR4-3200）；**PCIe Gen3 x16** 锁页 **`12.57 GB/s H2D / 13.21 GB/s D2H`**；WDDM 双向总和仅 **`12.84 GB/s`**（无全双工重叠） | 实测 |
| 主机内存带宽 | NUMA0 DDR4-3200：**`120 GB/s`**（30 线程）/ **`19.8 GB/s`**（单线程） | 实测 |
| 模型与基线 | `Qwen3.8-Flash-Next` SC117 `IQ3_XXS`（176B 总参 / ~6B 激活，48 层 = 36 GDN + 12 QSA，512 专家 top-10，262K 上下文，INT8 KV）；Strata `0.1.56`（`personal-0.1.56-p1`，31 GiB / 19,379 显存专家槽，`--kv-resident 32768`，`--batch 4 --batch-mtp`） | 实测 |

> **三条测量护栏**：(1) A6000 在 42 °C 冷态进入 CUDA Compute 即处于 P2 态 `7601 MHz`，空闲尾回落 `405 MHz`，故热节流必须以 NVML 热标志、`temp_max >= 87 °C` 或 `mem_mhz_p50 < 7500` 判别；(2) 解码窗长服从线性规律 `win_ms ≈ 6.64 + slope × avg_rows`，直接比较不同行宽的裸 `win_ms / avg_rows` 会受 6.64 ms 固定稠密截距偏置，必须用同行宽配对或去截距边际斜率 `(win_ms - 6.64) / avg_rows`（复算实现见 `moe_residency/ledger_v2.py`）；(3) 串行分族剖析（`STRATA_VERIFY_PROFILE=1`）关闭跨流并发，只作线索，关键路径必须由关闭剖析的 ABAB 消融确认。

## 2. Phase 1：五场景硬件吃满率与根因解剖

通过 44 臂独占基线实测与底层源码深潜，我将瓶颈严格分为 **物理墙**、**条件性模型墙** 与 **工程浪费** 三类：

1. **单路 100K 解码（`S1`）**：`~19.6 ms/窗`（`avg_rows ≈ 3.45`，约达 `713 GB/s` 字节下限的 `47.5%`）。单路纯 QSA 注意力仅 `0.32–0.61 ms/窗`；早先“QSA 注意力 7.07 ms”系源码打点遗漏（`batch_rec_` 漏打 stamp 11/12，把 `scores+topk+kv-resolve+attention` 四段混进同一桶）。
2. **四路 100K 并发解码（`S2`）**：基线 `41.92 ms/窗`（`avg_rows = 5.98`，去截距斜率 `5.90 ms/行`），频触 300 W TDP 功耗墙（0 热节流）。三项真工程浪费主导了退化：
   - `QSA_sel_res_attn` 退化 **2.48×** 达 **`9.47 ms/窗`**（`seg[5..9]` 窗口加权），根因是 `--kv-resident 32768`（`kv_mode=1`）绕过了 `QSA_SLOTS/BATCH_ATTN_ROWS`，且 `STRATA_ATTN_DAILY=1` 迫使 `pre75_attn()` 退回逐行；
   - `batch_rec_` 禁用了 `STRATA_SIDE_MIXER=2`，暴露 **`3.34 ms/窗`**（单路仅 `0.09 ms`）；
   - `bt_emit`（`2.90 ms/窗`）中 **96% 是 4 路串行同步 GPU `slot_mtp->draft()`**（每窗把 MTP 稠密权重 + 248,320 词表 `lm_head` 重复读 4 遍），纯主机 `printf/fflush` 仅 `0.11 ms/窗`。
   - 与此同时，4 路下 VRAM 命中专家仅 `0.98 ms/行`（已贴 `1.05–1.33 ms/行` 物理字节下限），4×100K 运行态 NUMA0 可用内存降至 `12.9 GiB`。
3. **小增量预填（`S3`，100K 上下文增量 130–600 tok）**：27 阶段拆解显示 `dequant 190–263 ms`、`gemm 184–384 ms`、`host grouping 95–115 ms`、全前缀 `kv stage` 恒 **`98–99 ms`**、`wait copy` 仅 `3–5 ms`，且每轮小增量触发 `391–473` 专家槽借用与回填（`56–68 ms`）。
4. **100K 长冷预填（`S4`）**：`39.7 s`（`2,425 tok/s`），达 FP32 算力约 `75%` 且顶 300 W TDP 功耗墙，属物理算力/功耗墙。
5. **100K 会话停放/恢复（`S5`）与宿主层（`E6`）**：
   - `STRATA_PARK_TRACE=1` 实证首次冷停放 **74–81%（`682–703 ms`）死在单线程 `std::vector::resize()` 缺页零填充**，而非拷贝（`130–240 ms`）；囤积第 14 条 100K 会话撞穿 NUMA0（`0.0 GiB`）溢出 NUMA1 后，`resize` 翻倍至 **`1,683–1,694 ms`**（冷停 `2.10–2.15 s`、恢复 `+120–160 ms`）。
   - 宿主层引擎外延迟从 `32.28 ms`（1K）涨到 `135.06 ms`（167K），但 Jinja 渲染仅 `1.28 ms`、暖分词仅 `2.90 ms`；**线性增长的 84%（`~86 ms`）来自 Python `','.join` ASCII 拼串（`45.75 ms`）+ Pipe/C++ `getline_fd` $O(N^2)$ 扫描（`~40.4 ms` 残差）**。

## 4. `personal-0.1.56-p2` 全栈联合终极大考（D1–D6）

我将 6 项通过审验的 RFC（20 提交、25 文件 `+3176/-272`，彻底剔除 `RFC-S1-L1`）合流至 `personal-0.1.56-p2`（`a1c2c904`，`strata.exe` SHA-256 `9ca1348a2ea895294b80cf0ee882a50273f31c16c5feaffd903d5c5c502baa17`），先全部跑通三套原生/Python 单测（`qsa_slots_parity` **16/16 逐位**、`conversation_cache_test` **`on_node=256 off_node=0, 4,877 checks`**、`test_ipc_delta` **5/5**），随后执行 `ALL OFF` 对 `ALL 6 ON` 的 D1–D6 全栈联合实测（`data/2026-11-22_a6000-v2/v2_rc_grand_exam.json`）。

### 4.1 D1 — 4×100K 并发解码 ABAB（全 4 臂严格同构 `918` 生成 token）

| `v2rc_off1` | ALL OFF | 21,403.3 | 5,926.2 | 15,477.0 | 42.03 | 33.27 | 1.82 | 2.90 | 5.898 | 5,769 MiB |

### 4.2 D2–D6 联合分项与运维红线

- **D2（单路 100K 解码）**：零退化（去截距斜率 `3.85` vs `3.90 ms/行`，`draft 2.46` vs `2.46 ms`）。
- **D3（100K 热增量预填）**：`155 tok <= 256` 纯 K3 实降 **`941.0 -> 726.6 ms`（`-214.4 ms`, `-22.8%`, `kv+qa 104->48 ms`, `0` 借槽）**；`527 tok > 256` 无缝切回 K3-B 零借槽（注：D3 的 `t240/t505` 基线含冷停放，纯 K3 预填收益以 `t130` 与 Wave 2 纯净 ABAB 为准）。
- **D4（100K 停放/恢复与 NUMA0 注记）**：冷停 **`1,056 -> 185 ms`（`-82.5%`, `5.7×`）**、`resize 701 -> 0.28–0.52 ms`、恢复 `273.3 -> 237.7 ms`。压满 8–10 个 100K 停放会话后 `node0_avail` 降至 `5.87 GiB (OFF) / 8.58 GiB (ON)`，证明必须配套 `STRATA_CONV_CACHE_TTL_S=1800` 与收紧 `--conversation-cache-slots`（`8–12`）长期守住 NUMA0 水位。
- **D5（167K 宿主层）**：`S2A-1 + S2A-2` 叠加将 167K 宿主层压至 **`62.92 ms`（较 Phase 1 `135.06 ms` 降 `-72.14 ms / -53.4%`）**，Python 代理净开销仅剩 `~10–15 ms`（低于 `25 ms` 的 Rust 代理重写门槛）。
- **D6（显存安全垫、红线与 10/10 验收）**：6 项全开稳态 `mem_free = 4,703–4,723 MiB`（高于 `2,048 MiB` 红线 `+2,655 MiB`），三协议 + 视觉 + 4 路并发验收 **`10 / 10` PASS**。
- **三条强制运维红线**：(1) 严禁强设 `STRATA_BATCH_MTP_ATTN_SLOTS=1`（保持未设置守 `<= 32 MiB` 自动门禁，强开在 `window==0` / 262K 额外吃 `387–580 MiB`）；(2) 稳态运行保持 `STRATA_PREFILL_SPARSE_CHECK=0`；(3) 严禁启用已证否并剔除的 `STRATA_BATCH_COMMIT_ASYNC=1`（`RFC-S1-L1`）。

## 5. 诚实证否清单与证据边界声明

完整记录已证否的路线可避免重复踩坑（见 `data/2026-11-22_a6000-v2/falsified_registry.json`）：

1. **单独 `STRATA_BATCH_COMMIT_ASYNC=1`（`RFC-S1-L1`）**：在 713 GB/s GDDR6 总线与 300 W TDP 争用下仅把 `commit` 挪入 `emit`，且导致 `gpu_wait` 尾溢 `+0.54–0.75 ms`（净益 `<0.5%`）；已否决剔除并由 `RFC-S1-L2` 替代。
2. **`STRATA_KV_PREFETCH=1`**：WDDM 下 PCIe Gen3 x16 无全双工重叠（双向总和仅 `12.84 GB/s`），实测与基线持平；改走 Selection-First 稀疏 KV（`RFC-K3-A`）。
3. **单路 `STRATA_QSA_SPLIT_ATTN=1`**：单路纯 QSA 注意力仅 `0.32–0.61 ms`（`-0.07 ms` 低于噪底）。
4. **Jinja 增量渲染缓存与 Rust HTTP 代理重写**：167K Jinja 仅 `1.28 ms`；`S2A-1+2` 后 Python 仅剩 `~10–15 ms`。
5. **RTX A6000（`sm_86`）跨层常驻 Megakernel**：6 MB L2 与 84 SM 共 8.3 MB shared memory 无法片上驻留数 GB HBM 权重，省不下 1 字节 DRAM 读取。
6. **沿用 v0.1 已证否项**：并发“时间片轮转”误判、`STRATA_HC_PERSIST=1` 与加深 HC 预取（`STRATA_HC_DEEP`）。
